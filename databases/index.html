Normalise a database to 3NF

Follow the same fictional school-club dataset from unnormalised data to 1NF, 2NF and 3NF.

1NF removes repeating groups and requires atomic fields. 2NF removes partial dependencies on a composite key. 3NF removes transitive dependencies between non-key attributes. The examples simplify the process to show each change clearly.

ACID properties

Atomicity

The complete transaction commits, or none of it does.

Consistency

Constraints remain valid before and after the transaction.

Isolation

Concurrent work is kept from interfering.

Durability

Committed changes survive failure in a proper DBMS.

This is a teaching model, not a multi-user database. No real locking, disk persistence or crash recovery takes place.

Redundancy and index trade-offs

Redundant repeated values can create update anomalies, but controlled redundancy may be used for speed or availability. Indexes improve lookup performance at the cost of additional storage and maintenance during writes.
